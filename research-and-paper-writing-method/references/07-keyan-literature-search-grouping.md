# 文献检索与文献库分组（搜 / 聚 / 分：鲸吞法）

来源说明：本文件为通用方法归纳，不含任何原书或课程的检索案例、真实课题、分组截图或个人数据。文中示例均为作者自拟的假设内容（"某材料""某性能"等为占位符）。

适用触发：文献检索式 / 检索词 / 同义词 / WoS / Scopus / 检索式测试 / 文献库 / EndNote 分组 / 鲸吞法 / 粗分 / 细分 / 特征词 / 去重 / 导入 / 导出 / 文献分组 / 找不到文献 / 领域没人做。

核心思想：检索是后续一切（选题、分组、写作）的源头。检索式不对，后面的工作都会漏。检索和分组都靠"测试"，用结果反馈调整，而不是先通读教程。

---

## 0. 三条总规则

1. 测试优于推理。每改一次检索式，看结果数量和前 5-10 条标题的相关比例，再决定下一步。
2. 先精简，再加限定。能删的检索词先删，直到结果量合适；再逐步加回必要限定。
3. 检索是"拼图碎片"。一次检索无法覆盖全部，多个检索式结果进同一个文献库，去重合并。

---

## 1. 检索式构建（四步）

### 步骤 1：拆成最小并列单元
把检索目标拆到不可再分的最小单元，每个单元分别找同义词，再用 AND 组合。避免给整个长词组找同义词（组合爆炸，且会漏检）。

示例（假设）：不要给"某材料的某性能测试方法"整体找同义词，而是拆成材料、性能、方法三个单元，各自列同义词。

### 步骤 2：获取专有名词的英文
- 百科类网站：拿到标准英文名。若词条不存在，去搜该词的新闻或科普报道，摘录真实文献标题中的英文表达。新闻标题里的英文常常比直译更贴近文献用词。
- 学术翻译工具（如 CNKI 学术翻译）：整串输入，按结果频次筛选，剔除低频和单字词。
- 中文文献检索：中文论文的标题常附英文标题，可从中文标题反查英文表达，比英文百科更贴近国内用语。
- 所有翻译工具输出都要用检索验证法二次核实（例如某翻译把正极译成了负极，需要用检索结果核对）。

### 步骤 3：处理单复数与通配符
- 用 `*` 通配：如 `exosome*`、`batter*`（覆盖 battery / batteries）。
- 注意通配符前必须至少有一个字符（`*xyz` 可以，`*` 单独开头不行）。
- 化学式：下标格式输入常会失败；用通配和省略形式（如 `Li*Ni`），再用 NOT 排除噪声。

### 步骤 4：在数据库中测试
- Web of Science 或 Scopus。精确短语用双引号，AND/OR 组合。
- 先限定在 Title 测试，结果不足再扩展到 Topic。
- 排序选按日期（最新优先），便于判断精准度。

### 删除测试（验证哪一步出错）
- 单独检索每个单元。两个单元各自结果都大，说明单元正确；合并后结果很少，说明是交叉冷门，而非检索词错。
- 若某单元结果异常少，说明该单元的写法或同义词有问题。

## 2. 检索式的标准形式（万能检索式）

```
(A1 OR A2 OR A3) AND (B1 OR B2 OR B3) AND (C1 OR C2)
```
- 每一行（对应检索界面的一个搜索栏）内部只用 OR 连接同一概念的同义词。
- 不同概念（行）之间用 AND。
- 不要在同一检索式里混用复杂的 AND/OR 嵌套，否则逻辑连自己都说不清。
- 标题与主题混用：标题行用宽松匹配，主题行用精确短语匹配，行间用 OR（见 2.1）。

### 2.1 标题与主题的不同精确度
- 标题行：不加引号，如 `term1* term2`（宽松，能捕捉两词分开出现的标题）。
- 主题行：加引号，如 `"term1* term2"`（精确，控制噪声）。
- 两行之间用 OR 连接。
- 经验对比：主题行全部不加引号可能爆炸到数万条，而精确限定可能只剩数百条。

## 3. 收窄与放宽的决策规则

| 结果数量 | 动作 |
|---|---|
| 太多（超过约 2 万条） | 加 AND 限定词；减少 OR 同义词；把部分检索词限定到标题；按学科或期刊限定 |
| 适中（2 万条以内，可用分组法处理） | 进入下一步（分组） |
| 太少 | 放宽：去掉修饰词（如把"某材料涂层"改为"某材料"）；去掉限定学科；改用上位概念 |

补充经验：
- 综述可把上限放宽到约 5 万条。
- 超过 2 万条时，优先补充应用领域词，而不是先补同义词。
- 结果太少时，最常见原因是把修饰词当成必需词。

### 3.1 少即是多（精简删除）
- 若某修饰词的同义表达多到无法穷尽，直接删除，用更大范围的检索覆盖。
- 删除后反而能找到作者未用该词但实质相关的文献（例如某工艺名称下的相关研究）。
- 删除后结果变多，可能正好带来"跨界联想"（如某材料在另一应用中的用法），是打开思路的手段。
- 问自己：这个词必须检索吗？去掉会怎样？
- 不是所有词都能删。删除过于泛化的词会引入无关结果；带有限定意义的词要保留。判断标准是语义，而不是词性。

### 3.2 极致拆分与"最小集合"
- 把检索词拆到最小后，逐个加回，测试每次加入的效果。
- 若加回某词后结果质量明显提升，保留；若只是增加噪声，删除。
- 结果已经很少（几百条以内）时，不要继续加限定，否则会过度收窄、漏检。

## 4. 排查噪声与漏检

### 4.1 噪声的常见来源
- 同形异义：同一词在不同语境指不同概念（如某词既指一种元素，又构成另一化合物的常用词）。
- 通配符误配：通配词根可能误中含该词根的无关词。
- 缩写误中：短缩写会命中含该字母组合的其他化学式；可用大小写匹配（Match Case）加空格精确匹配。
- 特定技术名：某词根会因通配而误中表征技术名称。
- 术语歧义：某术语在不同学科有不同含义。可用 `AND NOT` 排除，但要注意误伤。

### 4.2 NOT 排除（布尔否定）
- 只排除已确认的噪声模式，不要随意排除大类。
- 每排除一个词，用前 10 条标题复核是否误伤了相关文献。

### 4.3 漏检的常见原因
- 只用直译，不用真实文献用词（同一概念在文献中可能用不同动词或名词）。
- 检索词与作者用词不同：如作者用具体产品或型号名称，而不写上位类别名。
- 作者研究 A 但不提 A：用 A 的具体物质名或化学式补充（例如某类文献常用具体化合物名称，不一定出现该类别的总称）。
- 带连字符的复合词：可用"在结果内搜索"验证某词能否覆盖其连字符形式。
- 标题写法的变异：带符号的写法（如斜杠、@、下标形式）会漏掉普通单词检索。

### 4.4 "40% 相关度"停止规则
- 测试多个检索式时，看前 5-10 条标题的相关比例。
- 相关比例达到约 40%，即可停止收紧，不必追求完美排除噪声。
- 理想的检索测试结束时：约 20%-40% 以上的结果对自己有参考价值，并且有一个可做的方向。

### 4.5 "无人做"的检查
- 绝大多数"没人做"都是检索问题。在下结论前，至少测试 3 组以上检索式（改用同义词、上位词、具体物质名）。
- 找不到文献的情况：若是新交叉，可能确实新；若是两者本无关，说明是伪命题。

## 5. 检索"测试纪律"

1. 每次只改一小步，便于定位问题（类似小步提交）。
2. 记录每次检索式和结果数，形成演变序列（用于复盘和汇报）。
3. 数据库自带的检索历史可保存；也可用 WoS 的"创建跟踪服务"订阅新增文献。
4. 不要先通读教程。按钮和语法错误本身就是反馈，报错信息也能推断规则（如"截词符前必须有字符"）。
5. 工具之间的差异要自己测。WoS 与 Scopus 对同一检索式结果不同，可以都跑，结果都导入同一库，去重即可。
   - 理工科：WoS 结果大多被 Scopus 包含；Scopus 覆盖更广（含部分会议与非 SCI 期刊）。
   - 人文社科：两者互补，建议两个都跑。
6. 双引号的选择：标题检索不加引号，可能捕捉分开出现的词；主题检索用引号精确匹配，控制噪声。两种都试，看哪个更合理。

## 6. 导出、导入与去重（EndNote 工作流）

### 6.1 元记录（文献库的"形成记录"）
在文献库最前面插入一条以 `1-` 开头的记录（`1-` 使其排在最前），标题写明：检索引擎 | 检索式 | 检索日期。日后增量更新与追溯都依赖它。

### 6.2 导出
- WoS：每次最多导出 1000 条，分批导出（1-1000、1001-2000……）。导出格式选 EndNote Desktop（或 ISI 类）。必须勾选"包含摘要"（默认不含，后续处理需要摘要）。
- Scopus：RIS 格式，勾选摘要和关键词。新版界面单次可导出约 2 万条。
- 导出文件是中转文件，后续不再使用。

### 6.3 导入与去重
1. 新建文献库，文件名短、目录浅。
2. File → Import → File，选对应格式。Import Option 需试错：WoS 常用 ISI-CE；Scopus 选 RIS。
3. 去重设置：Edit → Preferences → Duplicates，选择判重字段（如 Title + Author + Journal）。
4. 导入时选 "Discard Duplicates" 去重导入；多源导入时可先 Import All，再手动 Find Duplicates 复核。
5. 手动查重：References → Find Duplicates，灰色高亮为疑似重复；建两个临时分组（一个存放确认不重复的，一个存放待删的），复核后删除，再删临时分组。

常见判重误差：
- 同一篇文献有在线预发表版（无卷期）与正式版两条记录。
- 作者格式差异（姓名缩写的写法不同）。
- 同名标题、不同作者（如多篇标题相同的文章）不是重复，必须人工看。

### 6.4 核对数量
- 检索总数 − 去重后数量 = 重复数。若差值异常，说明导入或导出有误。
- 用去重导入便于发现误操作（重复导入同一文件或漏导入）。

### 6.5 订阅新增
WoS 检索结果页可"创建跟踪服务"，定期邮件推送新文献。可积累一定量或遇到重要文献时才批量导入，避免过于频繁。

## 7. 鲸吞法：分组阅读文献（粗分）

名字来源：鲸鱼一口吞入大量浮游生物再过滤。第一轮宁可带入无关文献，也不要漏掉有价值的。第一轮要宽，后续逐步收窄。

### 7.1 六种目的场景（先判断你在哪种场景）
1. 不知道自己要做什么，想看大家在研究什么 → 粗分全库，俯瞰领域（场景1）。
2. 明确知道要解决的问题，想看别人做到什么程度，如何借鉴 → 直接检索 + 定向分组（场景2）。
3. 有几个候选方向，吃不准选哪个 → 对每个方向分别分组，横向对比（场景3）。
4. 方向已定，不知道具体做哪些实验或分析 → 建实验素材库（场景4）。
5. 结果不理想，或无法重复别人的工作 → 回到文献找遗漏与矛盾（场景5）。
6. 不知道如何发表 → 从高质量文献学写作与讨论结构（场景6）。

前五者最终服务于第六者（发表）。

### 7.2 粗分的标准流程
1. 把检索结果全部导入一个基准分组（如"总文献"，固定不变，用于每次关键词搜索的范围）。
2. 另建一个"未分类"分组（动态，随分组推进而变小）。
3. 排序：场景1 建议按标题或日期排序（打散期刊聚类造成的信息茧房）；已熟悉领域可按期刊排序。日期降序较随机，也能优先看到最新工作。
4. 浏览标题，提取"特征词"：能反映该文献独特切入角度的词（形貌、具体材料、功能、工艺）。
5. 在基准分组内搜索该词（Title Contains），命中结果建组，命名为检索词本身。
6. 全选命中结果，拖入新分组。
7. 从"未分类"中去除已分类文献（见 7.4）。
8. 循环，直到未分类文献数量足够小、命中数量递减。

### 7.3 特征词判断规则
应保留：
- 形貌（如纳米片、纳米纤维、三维结构、多孔）。
- 具体材料或元素组合（是否引入第二种元素、是否为某化合物的特定形式）。
- 功能定位（如粘结剂、电解液添加剂）。
- 工艺特征（如溅射、热解）。
- 反映独特性的修饰词：当某个词是共同主题（如"某材料基体"）时，修饰词才有区分度。

应略过：
- 检索本身已限定的范畴（所有命中文献都会有的词）。
- 泛指词（如 materials、stability）。
- 虚词（for、as、in）。
- 高频通用性能词（几乎每篇同主题论文都会提到的词）。
- 只是对某个词的进一步描述（若修饰的是工艺，则不是独立方向）。

取舍原则：
- 两个词语义重叠，保留更具体者。
- 拿不准时先搁置，看更多文献再决定。分错了可以改，代价小。
- 反义修饰（如"无某成分的"）会误收录，但不影响大局，之后可处理。

### 7.4 去重与"已分类"组集（批量操作）
- 分组后，已归入分组的文献仍留在"未分类"中（EndNote 的分组是标签，不是移动）。
- 批量去除：先点击"已分类"组集（Group Set），全选；再点"未分类"，已选中文献显示为浅灰，轻微拖动使其变为蓝色高亮；按 Delete 只从该分组移除（不删文献本身）。
- 注意：Delete 是"移除分组标签"，不是删除文献。彻底删除要拖入 Trash。

### 7.5 "文献分组 = 批量贴标签"
- 一篇文献可同时属于多个分组，不互斥。
- 代价：同一篇可能在多个分组中被重复看到，但不会遗漏。第一轮可接受。
- 后续用去重操作处理重叠。

### 7.6 全库搜索 vs 子分组搜索
- 在"未分类"中搜关键词会漏掉已分组文献中的相关文献（例如某分组中也可能有与之相关但归类不同的文献）。
- 因此关键词搜索应在基准分组中进行。
- 需要收窄时，在某分组内部继续搜索，范围自动限定到该分组。

### 7.7 批量分组的诊断与进度
- 进度判断：首轮命中数从上千逐渐降到几百、几十。命中数递减即接近尾声。
- 未分类文献降到原总量的 10% 左右，粗分基本完成。
- 数千篇级别的粗分，熟练后通常可在一个下午内完成（经验估计）。

### 7.8 分组名称与特殊符号
- 分组名用检索词，便于回溯。
- 同一分组由多个词共同定义时，用 `|` 连接（如 `carbon|C`、`microscopy|diffraction`）。
- 后期命中少的词可用中文统一命名，便于归并。
- 符号级检索（`/`、`@`、`-`）：本地文献库可检索符号，一次检索引擎通常不行，这是二次检索的独特优势。
- 用非完整单词（词根）：如某词根可一次覆盖多种派生写法。词根能一次覆盖多种形态写法。

### 7.9 "高频但不太高频"的阈值
- 过高：覆盖约八成文献的词按它分组等于没分。
- 过低：只命中个位数的词，效率低。
- 适中：命中数处于中段，且能覆盖同一含义的多种写法（如某词的符号形式、连字符形式）。

### 7.10 中转组技巧（清理噪声）
当某分组里混入噪声（如混入表征技术名称之类的无关词）：
1. 在该分组内搜索噪声词，结果移入临时"中转组"。
2. 逐篇检查：若目标词只出现在噪声语境，判定为噪声，留在中转组。
3. 若目标词在其他位置也出现（真正相关），从中转组移出。
4. 把剩余噪声从原分组中移除。
5. 中转组可改名保留为新分组，表征类研究本身可以是一个细分方向。

### 7.11 "限定在分组内搜索"验证
- 在子分组内搜索得到的结果，应与全库搜索相同（若不同，说明操作有误）。
- 这是复核机制：在基准分组名前标注当前应有数量，数量对不上即说明误操作。

### 7.12 误判与容错
- 字符串匹配会误判（如某修饰词在不同语境下含义不同）。粗分阶段不必追求零误判。
- 文献库中没有找到预期分组，不代表没有相关文献。可能是检索词没覆盖，回到 1-4 节补充检索。

## 8. 场景2、3与"目标缺失"

### 8.1 场景2：已有明确课题
1. 在粗分中找到与课题相关的分组。
2. 对该分组做二次分组（细分），操作同粗分，但搜索范围限定在该分组内。
3. 先在标题中验证特征词，合适后再扩展到摘要。不建议一开始就搜摘要（大量文献摘要含词，难以快速判断相关性）。
4. 确定细分方向后，检查相关分组。
5. 对课题相关文献做深入阅读和摘录。

### 8.2 场景2：导师给的方向在分组中找不到
- 说明检索式没围绕该方向组织。把该方向转成关键词，在总库重新检索。
- 若仍找不到，多半是检索式设置错误，逐项对照检索步骤排查。

### 8.3 目标缺失（为分组而分组）
典型反面情形（示例（假设））：一个 1500 篇的库，一次分组后仍有 400 篇未分；目标是某类检测相关的文献，却没有建立检测相关的分组。分组越分越乱。
处理：
- 不必把所有无关文献都分组。
- 对关心的那部分建专门分组，从中提取实验素材库（或代码/公式素材库）。
- 确认实验方案无完全一致报道，先动手做实验。
- 失败则回到此步检查是否遗漏。
- 其余未分类文献留在"未分类"即可。

### 8.4 场景3：多个候选方向
1. 每个候选方向分别建分组（同场景2）。
2. 横向对比：
   - 实验条件是否具备；
   - 实验素材库预估的实验周期能否接受；
   - 各分组文献发表的期刊，判断能投什么刊物；
   - 该方向能否写进毕业论文。
3. 综合选出优先尝试的方向；若受阻，可更换。

### 8.5 "不要为分组而分组"的检验
- 每一步问：这一步是否服务于当前目标？
- 好的分组过程应伴随思路越来越清晰、想动手的感觉。若感觉烦躁、越分越乱，说明方式有误。
- 分组程度没有标准答案。目标达成即可停，不以"分完"为标准。
- 可建一个"不相关 / 弱相关"分组收纳无关文献。

### 8.6 跳出本领域的一次分组
已有明确方向后，花约半天做一次跨领域粗分，借鉴思路。例如：若只搜本领域的核心词，会漏掉涉及相邻应用或完整系统分析的相关工作。

## 9. 摘要速读（不读全文也能抓住动机）

- 摘要通常只需读前两句：
  - 第一句：领域背景与现存问题。留意 Although、but 等转折词，其后往往紧跟缺点或未解决问题。
  - 第二句：作者的工作。留意 Herein、In this work、we 等信号词，其后紧跟作者的具体贡献或方法。
- 若第一篇背景交代不清，看第二、三篇，总有人写得清楚。
- 读摘要是阅读的一种，不必为此打开全文。

---

## 10. 文献库的增量更新

- 新检索式出现新同义词，可补充检索，只导入新增文献（去重导入自动跳过重复）。
- 发现某篇文献漏分组（表述特殊），针对该表述单独补检索，追加到已有分组。这是迭代，不是失败。
- 分组命名可随新词扩展（如把原名扩为"原名|新同义词"）。
- 文献库"形成记录"（元记录）保证每次更新可追溯。

---

## 11. 检索与分组的时间与效果基准

- 检索测试：约半天到一天完成一个主题的系统测试；可节省后续数月甚至数年的弯路。
- 检索结果导入与去重：数千篇级别约 1-2 小时（含导出分批）。
- 粗分：数千篇级别约一个下午。
- 细分（二次分组）：按分组数量，通常需要几小时到一天。
- 早期文献调研不扎实，是常见的延期原因之一。

## 12. 检查清单

- [ ] 把目标拆成最小并列单元
- [ ] 每个单元查英文（百科 / 新闻标题 / 中文文献 / 学术翻译），并交叉验证
- [ ] 删除测试：单元结果是否合理
- [ ] 万能检索式结构：行内 OR，行间 AND
- [ ] 结果数量在 2 万以内；太多收窄，太少放宽
- [ ] 前 5-10 条标题相关比例达约 40% 即可停止收紧
- [ ] 两个数据库都跑，结果去重合并
- [ ] 导出时勾选摘要；分批导出；元记录写入库首
- [ ] 导入选对 Import Option（ISI-CE / RIS 等，试错确定）
- [ ] 去重导入；核对检索总数与库数量差值
- [ ] 粗分：基准分组 + 未分类分组；特征词 → 搜索 → 建组 → 去未分类
- [ ] 分组名与检索词一致；多词用 `|`
- [ ] 每次分组后看命中是否递减；降到几十篇即接近尾声
